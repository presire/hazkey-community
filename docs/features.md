## 辞書

### ユーザ辞書 (品詞・動詞活用対応)

TSV形式で単語を登録できる辞書です。  

- 書式: `読み<TAB>単語<TAB>コメント[<TAB>品詞]`  
- 品詞 (固有名詞・人名・地名・動詞) を指定すると、変換エンジンの接続コスト評価に品詞が反映されます。  
- 設定UIの辞書タブから、追加・編集・インポート・エクスポートができます。  

### 動詞活用エンジン

azooKeyの`JapaneseConjugationBuilder`を移植したものです。  

- ユーザ辞書に登録した動詞から、全活用形を自動生成します。  
- 五段活用・一段活用・サ行変格に対応します。  

### 日本全国の地名辞書

都道府県・郡・市区町村・町域 / 大字のうち、変換エンジンが一発変換できない難読地名47,934件を、組み込み辞書として収録しています。  

- 設定: 設定UIの[変換]タブの[住所]チェックボックス (デフォルトOFF)  
- 一発変換できる地名は収録しないため、通常の変換候補の順位には影響しません。  

### 工学用語辞書

機械・電気・電子・情報工学、情報系サービス名、プログラム言語、データベース名、建築学、土木工学等の専門用語・名称のうち、  
変換エンジンが一発変換できないもの859件を、組み込み辞書として収録しています。  

- 設定: 設定UIの[変換]タブ[工学用語]チェックボックス (デフォルトOFF)  
- [住所]とは独立にON / OFFできます。  
- 読み・表記の出典は、SudachiDict (Apache-2.0) 他です。  
  ([hazkey-engineering-dictionary](https://github.com/presire/hazkey-engineering-dictionary)のNOTICEを参照)  

### Emoji 17直接変換

Emoji 17.0辞書による、絵文字の直接変換候補を追加します。  

- 設定: 設定UIの[拡張絵文字] (デフォルトON)  
- 通常変換の候補にのみ注入され、サジェスト・ライブ変換には混入しません。

## 変換・入力操作

### 文節境界調整

変換中に`[Shift] + [Left]` / `[Shift] + [Right]`で、文節の境界を直接調整できます。  

### ライブ変換トグル

`[Ctrl] + [Shift] + [L]` (デフォルト、設定で変更可能) で、ライブ変換のON / OFFを即座に切り替えられます。  

- OFF時のモードは記憶され、アプリ間の切り替えをまたいで維持されます。

### 予測候補の先頭表記固定

サジェスト候補にカーソルを合わせて`[F5]` (変更可能) を押下すると、その表記を先頭の固定表記として受理しつつ、続きを入力できます。  

### 誤字の訂正候補

読みに典型的な打ち間違いが含まれる場合、訂正した読みの変換候補を、先頭候補のすぐ後ろに表示します。  

- 設定: 設定UIの[変換]タブの[誤字の訂正候補を表示] (デフォルトOFF)  
- 通常変換と予測候補の両方に現れます。スコア比較と絞り込みを経て、最大3件まで提示されます。  
- 入力中 (preedit) の文字列は自動では書き換えません。訂正候補を選択したときだけ、その表記で確定します。  
- 文節が分かれる場合は、確定する先頭部分だけを訂正し、未変換の残りの読みはそのまま残します。  
- 対象:  
  - かなの連打 (長音・小書き文字の連なりを含む)  
  - 読みに残ったローマ字  
  - 隣接キーや母音の打ち間違い  
  - 撥音「ん」の打ち忘れ  

**注記の表示はフロントエンドで異なります。**  

| フロントエンド | 注記: `*[訂正]*`の表示 |
|:---|:---|
| **Fcitx 5.1.9以降** | 斜体で表示 |
| **Fcitx 5.1.8以前** | 候補自体は表示されるが、注記は付かない |
| **IBus** | `*[訂正]*` (日本語訳) の注記を灰色で表示 (斜体にはしない) |

Fcitx 5の最低要件は、従来どおり5.0.4のままです。  

### 候補ウィンドウのマウス選択

変換候補ウィンドウの候補を、マウスクリックでも選択できます。

## 学習データ・履歴

### 学習データの削除・履歴管理

- 候補フォーカス中に`[Ctrl] + [D]` (設定で変更可能、[候補学習削除ホットキー]) を押下すると、その候補の学習データを削除できます。  
- 設定UIの[入力履歴データの管理]から、入力履歴を選択して削除するダイアログも利用できます。  

### プロファイルごとの履歴分離

[プロファイル非依存の入力履歴]を無効にすると、プロファイルごとに学習データを分離して保存できます。

## ニューラル変換

### ニューラル変換設定の拡充 (Zenzai)

- プロファイルごとの、トピック・文体・好みの指定  
- 任意のGGUFファイルを使うカスタムモデルの指定  
- リッチ候補の、候補一覧 / サジェストの個別切り替え  
- GUIからのニューラル変換モデル管理 (ダウンロード・有効化・削除)  
- 右文脈: カーソル後ろのテキストを使用する (既定OFF、zenz-v3.2以降)  
- アラインメント区切り: 文節の区切りを移動した後の変換で、残りの読みを考慮する (既定OFF、zenz-v3.2以降)  

### 複数のニューラル変換モデルに対応 (zenz / jinen-v2)

標準の**zenz**系列 (Apache-2.0 / CC-BY-SA-4.0) に加えて、  
[togatogah](https://huggingface.co/togatogah)氏が公開するQwen3ベースの**jinen-v2**に対応します。  

- jinen-v2: small / xsmall (CC-BY-SA-4.0)  
- 量子化は、`f16` / `Q8_0` / `Q5_K_M` / `Q4_K_M`から選択できます。  
- 設定UIの表記は、モデルに依存しない[ニューラル変換]に統一しています。  

**jinen系モデルの扱い**  

- jinen系モデルは条件トークン (U+EE03〜EE06) を持ちません。  
  ただし、「ユーザープロファイル」は有効化中も入力でき、サーバ側で左文脈の先頭に区切り (句点「。」) を挟んで反映されます。  
  - プロファイルは正規化したうえで、末尾25文字を使用します。  
  - プロファイルの末尾が既に文末記号 (`。` `.` `!` `?`) の時は、句点を付けません。  
  - 文脈変換OFFでも有効です。左文脈の40文字枠とは別枠です。  
- トピック・文体・好みの3項目と、右文脈・アラインメント区切りは、jinen系では非対応です。  
  該当欄は自動的にグレーアウトされます。  

### ニューラル変換の事前ウォームアップ

サーバ起動時と設定の適用後に、モデルを事前ロードします。  
これにより、初回入力時のモデルロード待ちを解消します。

## 安定性・互換性

### サーバ管理の安定化

- クライアント更新時の、hazkey-community-serverの自動再起動  
- 不正な設定ファイルの、安全なパース  
- サーバプロセス管理の改善  

### マルチGPU環境のSIGILL回避

NVIDIAとAMD / Intel iGPUが同居する環境での、起動時クラッシュ ([上流 Issue #29](https://github.com/7ka-Hiira/hazkey/issues/29)) を解消します。  

- 隔離子プロセスによる、起動前のバックエンド安全確認  
- CPU専用への自動フォールバック  
- フォールバック発生時は、設定UIの[AI]タブに警告を表示します。  

詳細は、[トラブルシューティング](./troubleshooting.md)を参照してください。
